# Удалённое управление

splify умеет управляться удалённо: менять параметры AmneziaWG (обфускацию,
endpoint, ключи) и весь конфиг splify сразу на многих роутерах. Это устроено так,
чтобы работать в самых неудобных условиях — **за провайдерским NAT (CGNAT) без
белого IP** и **даже когда VPN-туннель упал**.

## Два канала

| Канал | Когда работает | Зачем |
|-------|----------------|-------|
| **Исходящий агент** (`splify-agent`) | всегда, пока жив WAN | роутер сам ходит наружу к панели — единственное, что работает за CGNAT и при упавшем туннеле |
| **Входящий REST API** (`/cgi-bin/splify-api`) | когда до роутера есть доступ (LAN / живой туннель) | прямое управление по токену |

Оба используют один бэкенд, поэтому ведут себя одинаково.

> Почему агент исходящий: до роутера за CGNAT нельзя достучаться снаружи. Поэтому
> роутер **сам** опрашивает панель по WAN — в обход туннеля и kill switch. Пока
> есть интернет на WAN, управление работает, даже если все туннели мертвы.

## Подключение к панели

Панель управления — отдельный инструмент (см. `splify-control` как референс). Она
выдаёт **«JSON подключения»**:

```json
{
  "internal": "http://10.8.0.1:8080",
  "external": "https://vpn.example.net:8443",
  "access_key": "одноразовый-ключ-доступа"
}
```

- `internal` — адрес панели через туннель/WG (пробуется первым, приватно);
- `external` — публичный адрес панели через WAN (резерв при упавшем туннеле);
- `access_key` — одноразовый ключ для регистрации.

Вставьте этот JSON на роутере: **LuCI → splify → Главная → «Удалённое
управление» → Подключить**, либо из консоли:

```sh
splify-ctl connect <<'JSON'
{"internal":"http://10.8.0.1:8080","external":"https://vpn.example.net:8443","access_key":"…"}
JSON
```

После этого роутер **сам генерирует свой ключ связи** и регистрируется на панели
(`access_key` после этого стирается). Дальше он опрашивает панель каждые N секунд
своим ключом и появляется в консоли.

## Что можно менять удалённо

- параметры AmneziaWG: обфускация `Jc/Jmin/Jmax/S1/S2/H1–H4/I1`, endpoint и порт,
  адреса, DNS, ключи; импорт целого `.conf`;
- весь конфиг splify: режим, интервал, kill switch, списки, туннели-failover,
  правила для устройств.

Панель помечает изменение как «к применению»; роутер на следующем опросе скачивает
его, применяет и переподключает туннель — **ровно один раз** (повторно не
применяет, петли переподключений нет).

## Входящий REST API

Включается на вкладке «Удалённое управление». Доступен на роутере по
`/cgi-bin/splify-api` с заголовком `Authorization: Bearer <токен>`:

```sh
# прочитать параметры интерфейса
curl -H 'Authorization: Bearer <токен>' http://РОУТЕР/cgi-bin/splify-api/wg/awg0
# поменять обфускацию + endpoint
curl -X POST -H 'Authorization: Bearer <токен>' \
  -d '{"awg":{"jc":"120"},"peers":[{"public_key":"…","endpoint_host":"1.2.3.4","endpoint_port":"500"}]}' \
  http://РОУТЕР/cgi-bin/splify-api/wg/awg0
# импорт .conf
curl -X POST -H 'Authorization: Bearer <токен>' --data-binary @client.conf \
  http://РОУТЕР/cgi-bin/splify-api/wg/awg0/import
```

> **Не открывайте** входящий REST в публичный интернет — он рассчитан на LAN/WG.
> Для управления извне используйте исходящий агент + панель. Ограничить источник
> можно полем «подсеть» (например `10.8.0.`).

## Site-to-site: связать LAN разных роутеров

Если у вас несколько роутеров splify в одной WG-сети, панель умеет связать их
локальные сети напрямую — хост из LAN одного офиса видит хосты в LAN другого.

Как это работает: каждый роутер сообщает панели свою LAN-подсеть (например
`10.8.1.0/24`). Панель собирает их со всех нод и рассылает каждому маршруты к
**чужим** LAN — трафик идёт через туннель, **без подмены адреса** (masquerade
выключен), поэтому хосты видят реальные адреса друг друга.

Включается одной кнопкой: **консоль панели → «Site-to-site меш» → Включить**.
Это **полный авто-меш** — добавили новый роутер, он автоматически появляется в
меше, и всем рассылаются обновлённые маршруты. На роутере при этом ставится
маршрут + правило firewall, туннель не переподключается.

> Маршрутизацию между LAN держит WG-хаб: у каждого пира на хабе должна быть
> прописана его LAN-подсеть в `AllowedIPs`, и включён форвардинг. Панель
> настраивает только стороны-роутеры (spoke).

## Безопасность

- Приватные ключи в отчётах роутера **маскируются** (наружу не уходят); панель
  присылает ключи только когда вы их осознанно меняете.
- Токен авторизует, но **не шифрует** — публичный адрес панели держите за TLS
  (nginx/caddy или встроенный `--tls-cert`).
- Веб-консоль панели привязывается **только к WG-сети** и наружу не торчит.

Полный протокол: `splify-control/PROTOCOL.md`.
