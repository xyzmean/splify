# splify — дружелюбный к пользователю форк wg-split

**Дата:** 2026-06-27
**Статус:** проектирование (ожидает ревью)
**Репозиторий:** `github.com/xyzmean/splify` (производный от `xyzmean/m9-split-router`)

## Контекст

`wg-split` (репо `m9-split-router`) — мощный «powertoy» для опытных пользователей:
OpenWrt-роутер превращается в split-tunnel шлюз. Заблокированные/иностранные IP
идут через WireGuard/AmneziaWG-туннель с приоритетным failover, RU/CN — напрямую,
опционально zapret обходит DPI на WAN. Настройка — через UCI/LuCI, ~2500 строк
shell + LuCI-приложение.

`splify` — **тот же движок, поданный как готовый продукт для обычного
пользователя**: установка одной командой, простой кнопочный интерфейс по
умолчанию, вся сложность спрятана под вкладку «Дополнительно», документация на
русском простым языком. `wg-split` остаётся отдельным проектом (powertoy,
развивается в первую очередь); `splify` — дружелюбная надстройка поверх той же
базы.

## Цели

1. Установка одной командой в терминале роутера (`wget … | sh`).
2. Простой кнопочный интерфейс по умолчанию; вся мощь — под вкладкой «Дополнительно».
3. Качественная, технически несложная документация на русском.
4. Пользователю показан только понятный функционал; жаргон (nftables/ip rule/режимы) скрыт.
5. Заложен фундамент под sing-box (без рабочего бэкенда).

## Не-цели

- Не вырезаем функциональность движка (failover, списки, zapret, killswitch, доктор, firewall-fix, дашборд — всё остаётся).
- Не реализуем рабочий sing-box-бэкенд (только фундамент).
- Не меняем сетевую логику маршрутизации/failover по сути — только подачу и брендинг.

## Архитектура

Структура пакетов и слоёв сохраняется как в upstream, меняются имена и UI-слой.

```
[Устройство в LAN] ─▶ [VPN-туннель] (через VPN: заблокированное)
                   └▶ [напрямую через WAN] (всё остальное; опц. zapret)
```

### Компоненты

| Компонент | Роль | Изменение |
|---|---|---|
| пакет `splify` | ядро: скрипты, служба, nft/dnsmasq-слой | ребрендинг из `wg-split` |
| пакет `luci-app-splify` | веб-интерфейс LuCI | новый «простой» вид + переименование |
| пакет `luci-i18n-splify-ru` | русский перевод UI | ребрендинг |
| `install.sh` / `uninstall.sh` | установка/удаление одной командой | новое |
| CI (`Dockerfile-apk`, `build.yml`, `release.yml`) | сборка и публикация `.apk` | ребрендинг проверенного пайплайна |

## Решения по дизайну

### 1. Брендинг (сквозное переименование `wg-split` → `splify`)

- Пакеты: `splify`, `luci-app-splify`, `luci-i18n-splify-ru`.
- Конфиг: `/etc/config/splify`; ubus-объект `splify`; rpcd-плагин `/usr/libexec/rpcd/splify`.
- Команды: `splify-apply`, `splify-doctor`, `splify-status`, `splify-failover`,
  `splify-firewall`, `splify-disable`, `splify-uninstall`, `splify-update-{ipsum,ru,domains}`,
  `splify-sync-nozapret`.
- Каталог библиотек: `/usr/local/lib/splify/common.sh`; nft drop-in `30-splify.nft`.
- Меню LuCI, ACL, заголовки, логи (`logread -e splify`).
- VERSION стартует с `1.0.0` (новый продукт), CHANGELOG обнуляется под splify.

Реализация: системный `sed`-рефактор по идентификаторам + переименование файлов
с префиксом `wg-split-`. Тесты (`bats`) и shellcheck обновляются под новые имена.

### 2. Интерфейс — два уровня

Меню **Сервисы → splify**, два пункта; по умолчанию открывается «Главная».

**Главная (простой кнопочный вид)** — новый экран `home.js`:
- Крупный тумблер **Вкл/Выкл** (включает/выключает разделение трафика — по сути
  `splify-apply` / `splify-disable` через существующий ubus `action`).
- Выпадающий список «Подключаться через» — выбор VPN-туннеля (WG/AWG-интерфейс).
  При наличии нескольких — это просто туннель приоритета #1.
- Крупный понятный статус: «Защищено · трафик через VPN», «Прямое подключение»,
  «Нет рабочего туннеля» — берётся из `splify-doctor --json` (overall + active path).
- Кнопка «Обновить списки» (вызывает обновление списков в фоне).
- Если доктор нашёл проблему firewall — кнопка «Починить автоматически»
  (`splify-firewall fix`), уже существующая логика.
- Раскрывающийся блок «Подробное состояние» — встраивает существующий живой
  дашборд (rx/tx по туннелям, таймлайн failover, диагностика) для любопытных,
  свёрнут по умолчанию.
- Никакого жаргона: ни «режимов», ни nft/ip rule, ни URL списков на этом экране.

**Дополнительно** — текущая форма настроек (`settings.js`), переименованная и
переписанная по-русски: режимы blocklist/full/split, туннели с приоритетами, URL
списков, zapret, killswitch, ручные CIDR/домены, привязки устройств, health-цели.
Вся мощь движка доступна здесь без потерь.

Существующий `status.js` (живой дашборд) переиспользуется как встраиваемый блок на
«Главной» и/или остаётся доступным; отдельного третьего пункта меню нет (так дружелюбнее).

### 3. Установка одной командой

`install.sh` в корне репозитория. Команда для пользователя:

```sh
wget -O - https://raw.githubusercontent.com/xyzmean/splify/main/install.sh | sh
```

Логика скрипта:
1. Проверить, что это OpenWrt с менеджером `apk` (24.10+/25.12+); иначе понятная
   ошибка с подсказкой.
2. Узнать последний GitHub Release через API
   (`https://api.github.com/repos/xyzmean/splify/releases/latest`), получить URL
   трёх `.apk` (`splify`, `luci-app-splify`, `luci-i18n-splify-ru`).
3. Скачать `.apk` во временный каталог, `apk add ./*.apk` (зависимости —
   nftables/curl/dnsmasq-full/ip-full/kmod-nft-core — подтянутся из штатных фидов
   как DEPENDS).
4. postinst пакета поднимает службу, cron и rpcd (как в upstream).
5. Напечатать следующий шаг: «Создайте VPN-туннель в Сеть → Интерфейсы, затем
   откройте Сервисы → splify и нажмите Вкл».

`uninstall.sh` — симметрично (`apk del luci-app-splify splify`).
Граничные случаи: нет интернета/релиза → внятная ошибка; уже установлено → апгрейд.

### 4. CI и релиз

Переиспользуется проверенный пайплайн upstream с ребрендингом:
- `Dockerfile-apk` — сборка `.apk` в OpenWrt SDK (PKGARCH:=all, один арх → один
  `.apk` под все цели), buildx gha-кэш для тяжёлого слоя ядра/зависимостей.
- `build.yml` — сборка артефактов на PR/ручном запуске.
- `release.yml` — ручной запуск с версией → публикация тега + релиз с `.apk`;
  тело релиза показывает установку через `wget … | sh`.
- `install.sh` дополнительно прикладывается к релизу как ассет.
- `test.yml`/`auto-version.yml` — обновляются под новые имена.

**Часть поставки:** после пуша запускается workflow «Release», проверяется, что
`.apk` собрались и приложены к релизу (иначе команда установки не работает).

### 5. sing-box как второй бэкенд (VLESS/Hysteria2, только импорт по ссылке)

Ранее заложенный seam (`type=wg|singbox` у эндпоинта, `ep_*`-диспетчер в
`common.sh`) доводится до рабочего бэкенда. Ключевое архитектурное решение:
**splify не отдаёт sing-box'у маршрутизацию.** Не используются `auto_route`/
`auto_redirect` (штатный для sing-box режим «сам маршрутизирует всё») —
splify как и раньше сам решает, какой трафик идёт через туннель, через
существующие nftables-метки/`ip rule`/таблицу 200. sing-box настраивается
пассивно: один TUN-инбаунд (`auto_route:false`, `auto_redirect:false`,
фиксированный `/30`-адрес, короткое `interface_name`) плюс один outbound
(vless или hysteria2, собранный из разобранной ссылки). Дальше это просто ещё
один L3-девайс, который существующий код `splify-apply`/`splify-failover`
маршрутизирует точно как WG-интерфейс. Из-за этого `tick()`/`set_vpn()`/
`degrade()`/`fail_closed()` и генерация nft-правил не меняются вообще —
они уже работают через протокол-независимые `ep_*`-диспетчеры и
`EP_LIST`/`endpoints_by_priority`.

**Область v1 — только импорт по ссылке.** Пользователь вставляет
`vless://…` или `hysteria2://…` (с сервиса/панели, тот же формат, что берут
v2rayN/NekoBox/Shadowrocket) в новую вкладку «sing-box» на «Главной»;
splify парсит её и создаёт эндпоинт. Поштучного редактирования полей нет —
чтобы поменять что угодно, пользователь вставляет новую ссылку поверх той же
секции. Разобранная ссылка (`uri`) хранится как источник истины в новой
секции `config singbox`; кэшированные поля (`protocol`/`server`/`port`/…)
только для отображения, перегенерируются при каждом рендере и никогда не
считаются авторитетными — застоявшийся кэш может дать неточную сводку в UI,
но не может привести к рассинхронизации с реально запущенным конфигом.
Поддержаны основные параметры vless (`flow`, `security` none/tls/reality,
`sni`, `pbk`/`sid`, транспорт tcp/ws/grpc/http/httpupgrade/xhttp) и hysteria2
(`password`, `sni`, `insecure`, `obfs`+`obfs-password`); менее значимые
параметры (`fp`, `alpn`, `spx`, `headerType`, `mode`, `authority`,
`pinSHA256`) молча игнорируются, а не блокируют импорт. IPv6-адрес сервера
(`[::1]`) в v1 не поддержан и отклоняется явной ошибкой при импорте, а не
молча ломается.

**Модель процессов — по инстансу на эндпоинт, симметрично WireGuard.**
Новый init.d `splify-singbox` поднимает N именованных procd-инстансов (по
одному на каждую `config singbox` секцию) через `sing-box run -c <файл>`;
рендер конфига (`splify-singbox-render`) гоняет `sing-box check` перед
подстановкой и не трогает уже работающий хороший конфиг при неудаче нового
импорта. Компромисс, который явно документируется пользователю: WireGuard —
модуль ядра, лишний туннель почти бесплатен; sing-box — полноценный
user-space процесс на Go, и каждый дополнительный sing-box-эндпоинт — это
отдельный процесс со своим потреблением памяти. На роутерах с небольшим ОЗУ
несколько параллельных sing-box-туннелей заметно весомее по памяти, чем то
же количество WG-туннелей.

**Мягкая (runtime) зависимость, как у zapret.** Пакет `sing-box` не входит в
`DEPENDS` пакета `splify` и не собирается в CI-образ — каждая точка
использования (`splify-singbox` init.d, `ep_bringup`/`ep_restart` в
`common.sh`, доктор) сама проверяет `command -v sing-box` и корректно
деградирует (эндпоинт считается недоступным, без падений и без
краш-цикла), если пакет не установлен. `splify-doctor` получает отдельную
проверку «пакет sing-box не установлен» с готовой командой-подсказкой
(`opkg install sing-box`).

**Известные ограничения v1** (документируются, не считаются багами):
нет живых счётчиков rx/tx и «возраста handshake» для sing-box-эндпоинтов
(дашборд показывает только «есть/нет», без графика и без freshness-индикатора
— у sing-box нет дешёвого аналога `wg show latest-handshakes`); нет
поддержки IPv6-адреса сервера.

### 6. Документация (RU, простым языком)

- `README.md` — на русском: что это, установка одной командой, быстрый старт.
- `docs/ru/` переписывается под пользователя:
  - `Home.md` — обзор;
  - `Установка.md` — `wget … | sh`, требования;
  - `Быстрый-старт.md` — создать туннель → нажать Вкл;
  - `Как-это-работает.md` — одна простая схема, без жаргона;
  - `Простой-режим.md` — экран «Главная»;
  - `Дополнительно.md` — обзор продвинутых настроек;
  - `Решение-проблем.md` — частые проблемы простым языком;
  - `FAQ.md`;
  - `sing-box.md` — «в планах».
- Технические внутренности (nft/ip rule/доктор) — один короткий раздел «для
  продвинутых», без перегруза основной документации.

## Поток данных (без изменений по сути)

nft-метки → `ip rule` → таблица 200 → активный туннель. Цепочки регенерируются из
UCI (`splify-apply`); служба `splify` крутит failover-цикл и самовосстанавливает
IP-сеты. Меняются только имена и слой представления (LuCI), не сетевая логика.

## Обработка ошибок

- Установщик: понятные сообщения при не-OpenWrt системе, отсутствии apk, отсутствии
  сети/релиза, уже установленном пакете.
- «Главная»: статус и кнопка «Починить автоматически» вместо непонятных FAIL.
- До создания туннеля весь трафик безопасно идёт через WAN (как в upstream).

## Тестирование

- `shellcheck` на всех скриптах (под новыми именами).
- `bats`-юнит-тесты переименовываются и проходят.
- Сборка `.apk` в CI зелёная; релиз публикует артефакты.
- Ручная проверка установщика: парсинг latest-release и подстановка URL `.apk`
  (логику можно прогнать в режиме dry-run без реального роутера).

## Риски

- **Сборка `.apk` в Actions** — главный внешний риск (OpenWrt SDK в облаке). Берём
  проверенный пайплайн upstream; возможны 1–2 итерации в CI.
- **Широкий diff ребрендинга** — механический, но затрагивает много файлов;
  снижается аккуратным `sed` + прогоном shellcheck/bats.
- **Новый экран «Главная»** — основная новая разработка; опирается на уже
  существующий ubus `action`/`status`, поэтому без новой бэкенд-логики.

## План поставки (верхнеуровнево)

1. Ребрендинг `wg-split` → `splify` (файлы, идентификаторы, конфиг, команды, CI, тесты).
2. Новый экран «Главная» (простой вид) + переименование «Дополнительно».
3. `install.sh` / `uninstall.sh`.
4. Фундамент sing-box (поле type, заглушки диспетчера, пункт UI, доки).
5. Документация на русском.
6. Создать репо `xyzmean/splify`, запушить, прогнать релиз, проверить `.apk`,
   проверить команду установки.
