# История изменений

## Не выпущено
- **FACEIT: обход блокировок игрового трафика отдельным nfqws** (новое) —
  чинит подключение к FACEIT/CS2 на DPI-блокировках (ТСПУ, Ростелеком и др.) с
  минимальным оверхедом на пинг; роутерный аналог пресета
  `complex multidisorder (game filter)`:
  - **архитектурно splify запускает свой собственный экземпляр nfqws** на
    отдельном `qnum=192` (а не полагается на nfqws от zapret'а — тот применяет
    desync только по своим `--filter-*` правилам и пропустил бы FACEIT
    нетронутым). Это официально поддерживаемый паттерн zapret
    (`init.d/custom.d.examples.linux/50-nfqws-ipset`), в духе того, как splify
    уже запускает sing-box через procd;
  - **ограничение IP-хостеров делается на уровне nft**, не через `--ipset` флаг
    nfqws (последний upstream помечает как «VERY INEFFECTIVE»: каждый пакет всё
    равно идёт в userspace). Цепочка `splify_faceit_queue_postrouting` ставит
    `queue num 192 bypass` только для `ip daddr @splify_faceit_v4` на портах
    UDP 27015-27036 (геймплей) и TCP {443, 27015-27030} (лобби/API);
  - **`bypass` флаг на queue** — если nfqws от splify'я отсутствует или упал,
    FACEIT-трафик **не дропается**, а идёт напрямую без изменений (критично для
    игр: мёртвый демон никогда не рвёт матч);
  - **списки IP обновляются автоматически**: раз в сутки `splify-update-faceit`
    качает IPv4-диапазоны хостеров, у которых FACEIT арендует серверы (OVH,
    Hetzner, Google Cloud, i3D.net — своего ASN у FACEIT нет) из
    `rezmoss/cloud-provider-ip-addresses` (через jsDelivr зеркало) + i3D geofeed;
  - **параметры desync настраиваются в LuCI** (вкладка «Списки» → «FACEIT»):
    режим/cutoff/repeats для UDP и TCP отдельно, выбор хостеров. По умолчанию
    UDP=`fake cutoff=d2 repeats=1` (минимум оверхеда ≈ Gv1, лучший пинг),
    TCP=`fake,multidisorder cutoff=n3 repeats=6` (как OVH-TCP-блок в complex
    multidisorder);
  - **пакет zapret/nfqws — необязательная runtime-зависимость**, как sing-box:
    сервис self-gates на наличие бинарника `nfqws` в PATH и на
    `faceit_enabled`, поэтому включать init-скрипт всегда безопасно; до
    установки zapret'а сервис просто тихо выходит, а трафик идёт напрямую;
  - **не трогает `/etc/config/zapret`** — splify не владеет конфигом zapret'а
    (та же принципиальная позиция, что и с firewall'ом). Даже если пользователь
    удалит Gv через Zapret-Manager, FACEIT-обход продолжит работать.
- **sing-box: второй бэкенд туннеля, импорт по ссылке `vless://`/`hysteria2://`**
  (новое) — рабочая реализация ранее заложенного seam (`type=wg|singbox`):
  - вкладка «sing-box» на «Главной»: вставляете ссылку-приглашение от вашего
    сервиса/панели (тот же формат, что принимают v2rayN/NekoBox/Shadowrocket) —
    splify разбирает её и создаёт эндпоинт. v1 — **только импорт целиком**, без
    редактирования отдельных полей; чтобы что-то поменять, вставляется новая
    ссылка поверх той же секции. После импорта эндпоинт всё равно нужно
    добавить в «Дополнительно» → «Туннели» с приоритетом — так же, как
    WG-туннель, только типом `sing-box` и синтетическим именем вместо выбора
    сетевого интерфейса;
  - **архитектурно splify не отдаёт sing-box'у маршрутизацию.** Сознательно не
    используются штатные `auto_route`/`auto_redirect` sing-box (его обычный
    режим «маршрутизируй всё сам») — вместо этого TUN настроен пассивно
    (фиксированный `/30`, `auto_route:false`), а решение, какой трафик идёт
    через туннель, как и раньше принимает только nftables/`ip rule`/таблица
    200 самого splify. Из-за этого sing-box-эндпоинт участвует в том же
    failover/приоритете/kill switch/firewall без единой строчки
    спец-логики в `splify-failover`/`splify-apply` — они уже были
    протокол-агностичны через `ep_*`-диспетчер;
  - **несколько sing-box-туннелей одновременно** поддержаны симметрично
    WireGuard (свой процесс + TUN-девайс на каждый, в общем списке
    приоритетов), но с явной оговоркой по цене: WireGuard — модуль ядра,
    лишний туннель почти бесплатен, а каждый sing-box-эндпоинт — отдельный
    user-space процесс (Go) со своим расходом ОЗУ — на роутерах с небольшим
    объёмом памяти несколько запасных sing-box-туннелей заметно дороже, чем
    столько же WG;
  - пакет `sing-box` — **необязательная runtime-зависимость**, как `zapret`:
    не входит в `DEPENDS` пакета `splify`, не ставится в CI-образ; каждая
    точка использования (init.d `splify-singbox`, диспетчеры `common.sh`,
    доктор) сама проверяет `command -v sing-box` и корректно деградирует
    (эндпоинт считается недоступным, без падений/краш-цикла) при
    отсутствии пакета; `splify-doctor` получил отдельную проверку с
    готовой подсказкой `opkg install sing-box`;
  - поддержаны основные параметры `vless://` (`flow`, `security`
    none/tls/reality, `sni`, reality `pbk`/`sid`, транспорт
    tcp/ws/grpc/http/httpupgrade/xhttp) и `hysteria2://` (`password`, `sni`,
    `insecure`, `obfs`+`obfs-password`, диапазон портов через запятую);
    второстепенные параметры (`fp`, `alpn`, `spx`, `headerType`, `mode`,
    `authority`, `pinSHA256`) молча игнорируются, а не блокируют импорт;
    IPv6-адрес сервера (`[::1]`) в v1 не поддержан и отклоняется явной
    ошибкой при импорте вместо тихого некорректного разбора;
  - известное ограничение v1: нет живых rx/tx-счётчиков и «возраста
    handshake» для sing-box-эндпоинтов на дашборде (только «есть/нет») — у
    sing-box нет дешёвого аналога `wg show latest-handshakes` без включения
    отдельного stats-порта.
- Ревью UI/UX, архитектуры и оптимизации (агентный прогон по всей кодовой базе):
  - **гонка в `splify-apply`.** Скрипт — единственный писатель `30-splify.nft` —
    вызывался без блокировки одновременно из CGI (`import`/`wg-set`), `splify-ctl
    action apply`, `splify-firewall fix`, исходящего агента и суточного
    самолечения списков; два параллельных прохода могли гонять `mv` во временный
    файл и поставить недописанный/устаревший ruleset. Добавлена сериализация
    через `flock` (как у `splify-failover`), плюс явный WARN в лог, если
    установка ruleset или `fw4 reload` всё же не удались (раньше «applied»
    писалось в лог безусловно);
  - `splify-apply`/`splify-doctor` пересчитывали список туннелей по приоритету
    (`endpoints_by_priority`/обход UCI) по 2–3 раза за проход — закэшировано;
  - утечка приватного ключа между интерфейсами: в панели AmneziaWG быстрое
    переключение туннеля во время «Показать ключ» могло подставить приватный
    ключ ПРЕДЫДУЩЕГО интерфейса в форму текущего (гонка ответов RPC) — исправлено;
  - четыре копии одного и того же `notify()` сведены в `lib/notify.ts`; добавлен
    запасной тост в самом приложении на случай, если `window.ui` недоступен —
    раньше в этом случае обратная связь по действию пропадала совсем (только
    `console.log`);
  - страница «Дополнительно» (настройки) больше не подменяется полноэкранной
    ошибкой, если после успешного сохранения обновление данных внезапно упало —
    форма остаётся на месте, ошибка показывается баннером с повтором; то же для
    вкладки «Удалённое управление» (раньше падение первой загрузки навсегда
    подвешивало её на «Загрузка…» без возможности повтора);
  - опция «sing-box (скоро)» в типе туннеля стала недоступна для выбора — раньше
    её можно было сохранить и применить, хотя бэкенда под неё нет;
  - убран мёртвый код: неиспользуемый `select.tsx` (Radix Select, нигде не
    импортировался), нетронутый шаблонный `App.css` и рассинхронизированный
    `luci-view.js` (устаревший дубль реального загрузчика вида, с неверным
    именем файла в комментарии).
- Исправления failover:
  - **туннель снова поднимается сам после сбоя WG-сервера.** После ухода в
    fallback (wan/zapret/killswitch) демон проверял кандидатов только через
    `ifup`, который на уже поднятом интерфейсе — no-op в netifd: «заклинивший»
    туннель (протухший резолв endpoint-хоста после смены IP/DDNS, зависший
    UDP-путь за CGNAT, ошибка proto в netifd) никогда не пересоздавался, и
    splify оставался в fallback даже после восстановления сервера — до ручного
    переввода конфига в дашборде (который делает ровно `ifdown`+`ifup`).
    Теперь «поднятый, но нездоровый» кандидат получает полный пересетап
    (ifdown/ifup со свежим резолвом endpoint) на каждом тике; трафика он не
    несёт, так что это ничего не рвёт;
  - проходы failover сериализованы (flock): одновременный тик демона и
    разовый проход из Save&Apply/агента могли удалить probe-правило друг у
    друга посреди ping-проверки и устроить ложный «stuck endpoint» с лишним
    рестартом туннеля;
  - активный интерфейс при killswitch проверялся дважды за тик (лишний раунд
    ping-проб при каждом сбое) — теперь один раз;
  - `wg_handshake_age` берёт самый свежий handshake среди всех peer'ов
    интерфейса, а не первую строку `wg show` (на multi-peer туннеле мёртвый
    первый peer выглядел как мёртвый туннель).
- Удалённое управление (новое):
  - единый бэкенд `splify-ctl` — экспорт/импорт всего конфига splify + параметров
    каждого интерфейса WireGuard/AmneziaWG (обфускация Jc/Jmin/Jmax/S1/S2/H1–H4/I1,
    endpoint, ключи), импорт целого `.conf`; приватные ключи маскируются;
  - исходящий агент `splify-agent`: роутер сам опрашивает панель управления по
    WAN (в обход туннеля и kill switch) — работает за CGNAT и при упавшем туннеле;
    приоритет внутреннего адреса (через туннель), резерв — внешний (через WAN);
  - входящий REST API `/cgi-bin/splify-api` с авторизацией по токену — прямое
    управление по LAN/WG;
  - подключение к панели через «JSON подключения» (внешний+внутренний адрес и
    ключ доступа): роутер генерирует свой ключ связи и регистрируется (enroll);
  - счётчик generation на стороне панели — желаемый конфиг применяется один раз,
    без петли переподключений туннеля;
  - референс панели управления `splify-control` (Python, без зависимостей):
    публичный node-API + веб-консоль, доступная только из WG-сети; см.
    `splify-control/PROTOCOL.md`.
  - **site-to-site меш**: каждый роутер сообщает свою LAN-подсеть, панель
    собирает их и рассылает каждому маршруты к чужим LAN (через туннель, без
    masquerade — реальные адреса). Полный авто-меш включается одной кнопкой в
    консоли; добавил роутер — он автоматически в меше. На роутере применяется
    маршрут + исключение из masq, без переподключения туннеля (`splify-ctl
    sites-apply`).
  - редактор AmneziaWG расширен до полного набора (I1–I5/J1–J3/S3/S4/itime),
    имя ноды (`node_id`) задаётся из LuCI; генерация токена больше не зависит от
    `base64` (которого нет в busybox) — иначе токен выходил пустым и enroll падал.
  - новый веб-интерфейс на «Главной» (React): блочный дашборд со stat-плитками,
    вернулись все кнопки и история событий, панели «AmneziaWG» и «Удалённое
    управление».
- Перенесены полевые исправления из апстрима m9-split-router:
  - синхронизация списка обхода (nozapret) больше не перестраивается и не пишет
    в лог на каждом тике, если список не изменился — нет засорения syslog и
    лишней нагрузки на CPU;
  - диагностика теперь показывает реальный вклад списка ru/cn (число записей в
    файле), а не пустой счётчик в режимах blocklist/split.

## 1.0.0
- Первый релиз splify: установка одной командой, простой интерфейс,
  расширенные настройки под вкладкой «Дополнительно», документация на русском.
- Заложен фундамент под sing-box (пока без рабочего бэкенда).
